# ISEF Research Plan / Project Summary

**Student Name(s):** Nischal Keshav
**Project Title:** Optimizations to Quantum Computing Architectures Utilizing Classical Structures

## 1. Rationale

**Background.** Most quantum computing research assumes an abstract circuit model and leaves open how a real machine should organize memory and schedule operations. In an earlier working paper I proposed an architecture with three parts: a read-only memory sector that behaves as an oracle and is kept separate from a small set of active qubits; a classical controller that carries out Pauli-X and SWAP gates by editing an address table instead of firing quantum gates; and a clock that packs as many operations as possible into each tick.

**Why it matters.** Today's quantum computers are limited by error rates and qubit counts. Every gate and every clock tick adds error, so an architecture that removes gates or shares qubits extends what existing hardware can run without any new technology.

**Gap addressed.** The claims in the working paper were calculated by hand and treated the oracle lookup as free. Published work shows that quantum memory lookups are expensive (Jaques & Rattew, 2023) and that a standard design answers only one query at a time (Xu et al., 2025). Related techniques exist separately, including Pauli frame tracking (Knill, 2005) and qubit relabeling in compilers (Li et al., 2019), but they have not been combined and evaluated as a single memory architecture. This project tests the architecture's claims with formal rules and simulation.

**Impact.** The benchmark algorithms, Grover's search and Shor's factoring, underlie applications in materials science, optimization, and cryptography. Mathematically, the project gives a precise statement of which quantum gates can be replaced by classical bookkeeping and which cannot.

## 2. Research Question(s), Hypothesis(es), Expected Outcomes

**Research question.** Within the constraints of unitary evolution, is it possible to replicate classical reversible functions inside quantum computers without applying quantum gates?

**Engineering goal.** Design an architecture that takes any quantum algorithm represented as a Clifford circuit and, where compression is possible, converts it to a compressed version that uses fewer quantum gates.

**Expected outcomes.**

- **A proof.** In any Clifford circuit, every Pauli gate (X, Y, Z) and every SWAP can be replaced by a classical update to the controller's address table, with results corrected at measurement.
- **A working compiler.** A program that takes a Clifford circuit and returns the compressed circuit with its address-table updates, verified by simulation to give the same outputs as the original.
- **Measured savings.** Reductions in gate count and circuit depth that grow linearly with the number of qubits, replacing the hand estimates in the working paper.
- **A clear boundary.** Entangling gates such as CNOT cannot be removed, so the expected answer to the research question is "yes, for a specific class of functions." The project will state that class exactly and test how far it extends beyond Clifford circuits, to gates such as T.
- **System effects.** Evidence on whether compressed circuits succeed more often under noise, and whether a shared oracle still saves qubits once lookup cost is counted.

## 3. Procedures / Methodology

### Materials / Tools

Personal computer; Python 3 with Qiskit and Qiskit Aer (circuit construction and noisy simulation), Stim (fast error simulation), NumPy, and Matplotlib. No external datasets are needed. All test circuits are generated by code.

### Steps

1. **Formal model.** Define the address table and flag rules. Prove that an X flag or address swap followed by any unitary *U* is equivalent to the original circuit, and derive how flags propagate through each Clifford gate (H, S, CNOT). Then examine what happens at the non-Clifford T gate.
2. **Compiler pass.** Implement the rules as a Qiskit pass that removes X and SWAP gates and updates the address table. Verify correctness with the Stim stabilizer simulator at large sizes and with state vectors for up to about 16 qubits.
3. **Gate-savings benchmark.** Generate Clifford circuits (Bernstein–Vazirani, GHZ state preparation, error-correction syndrome extraction, and random Clifford circuits) for *n* = 4 to 64 qubits, then QFT, Grover, and Shor circuits as the extension beyond Clifford. Record total gates, two-qubit gates, and depth before and after the pass. Use Qiskit's standard optimizing compiler as the baseline so the comparison is fair.
4. **Oracle lookup cost.** Build bucket-brigade and table-lookup memory circuits (Giovannetti et al., 2008; Babbush et al., 2018) for *N* = 8 to 1,024 entries and record qubits, gates, and depth per lookup.
5. **Shared-oracle test.** For *k* = 1 to 8 Grover instances, compare duplicated oracles against one shared, queued oracle. Record total qubits and total depth.
6. **Noise simulation.** Simulate small instances with amplitude-damping and dephasing noise, including idle error on waiting qubits. Vary the number of operations per clock tick and measure success probability.

### Data Analysis

- **Metrics:** gate count, two-qubit gate count, circuit depth in clock ticks, total qubits, and algorithm success probability.
- **Gate savings:** linear regression of gates saved against *n*, reporting slope and R² for each circuit family.
- **Shared oracle:** qubits and depth plotted against *k* and *N* for both designs, with the break-even point identified.
- **Noise:** success probability from at least 1,000 shots per configuration across multiple random seeds, compared between the two models with 95% confidence intervals.
